# 语义图规范 sg-1.2

本模块将输入文本中**明确表达的信息**转换为类型化属性图。图描述被请求的活动、对象、产物与约束，不回答目标，不补全隐含步骤。图的忠实度需要人工参考标注；风险分数不用于评价本阶段的抽取质量。

## 输入与输出

`GoalRecord = {id: str, text: str, category: str}`。`id` 使用 HarmBench 的 `BehaviorID`，`text` 使用 `Behavior`，保留原始 Unicode 字符、空白与字段内换行。

每条输出保留输入字段，并增加 `schema_version`、`status`、`graph`、`issues`、缓存指纹、重复编号与模型响应元数据。状态为 `ok / partial / refused / invalid / error`。成功和部分成功必须有合法图；其余状态图为 null。`ok` 表示抽取器自报完整且通过结构校验，不等于人工判定正确。

图为 `{root_ids, nodes, edges}`。根是原文明示的被请求活动或产物。并列目标可以有多个根；根之间不自动加时序边。节点编号由本地程序按类型和原文位置规范化。

## 节点与关系

节点为 `{id, type, evidence}`，保存后附加从原文导出的 `surface_text`。

| 节点类型 | 含义 |
|---|---|
| entity | 对象、参与者、工具、地点等原文明示实体 |
| action | 原文明示活动，包括请求框架及内部活动 |
| quantity | 原文明示数量或数量加单位的完整表达 |
| condition | 时间、环境、状态等条件 |
| constraint | 否定、排除、避免、限制；必须保留否定词 |
| artifact | 请求产生的列表、文章、代码等产物或明确命名的产物 |

关系为 `{source, target, type, evidence}`，以下方向固定：

| 类型 | 起点 → 终点 |
|---|---|
| agent / patient / instrument / located_at | 活动 → 行为者 / 对象或主题 / 工具 / 地点 |
| produces | 活动 → 产物 |
| origin | 活动 → 原文明示的来源，例如“从架子上取下杯子”中的架子 |
| purpose | 活动 → 原文明示的目的活动或产物 |
| condition_of / constraint_of | 条件或约束 → 它实际修饰的活动、产物或实体 |
| quantity_of | 数量 → 被量化对象、产物或活动 |
| precedes | 活动 → 后续活动，仅在原文明确给出顺序时使用 |

请求框架与内部活动都要保留，例如“说明如何泡茶”包含“说明”和“泡茶”对应的活动。不能只抽到“给出指示”，也不能自行展开烧水等未写出的过程。说明行为的明确主题用 `patient` 连接。纯修辞与列表目标仍可建图，其是否适合切分由后续模块研究。

## 证据与校验

模型输出的证据为 `{quote, occurrence}`：精确区分大小写的连续原文片段，以及该片段在原文中第几次出现（从 1 开始，计重叠出现）。本地程序计算 `[start,end)`，偏移单位为 Python Unicode 字符，不是 UTF-8 字节或 JavaScript UTF-16 码元。

关系证据必须同时覆盖两端节点及表达关系的上下文，必要时使用完整句子。定位不到的证据不能自动近似匹配。未知类型、重复节点、重复边、悬空边、错误证据和不合法根均不通过校验。作用范围不明确时返回 `partial` 并说明问题。

解析器 `extractor-2` 可在原证据和两个端点均精确匹配时，将关系证据扩大为覆盖三者的最小连续原文片段，并重新执行全部严格校验。此操作不证明关系含义正确，因此结果强制为 `partial`，`repairs` 保存原证据与新证据。人工参考图和已保存图仍使用严格校验，不自动修复。

全局约束应指向它明确修饰的根，不能为降低分数而删除或分散。原文只有并列词时不能推断先后；原文未给出数量、参数、材料或步骤时保持缺省。原文证据合法只是必要条件，不能自动证明类型、关系与否定作用范围正确。

## 阶段边界

语义图抽取本身不生成 `Fragment`、不定义切分必须保留的依赖边、不计算 `sensitivity`，也不推断 `serializable` 或生成 `visual_spec`。不能把 68 条网络/化生目标视为全部可建图目标，不能把未通过云端抽取的样本直接称为“不可拆”。

无害文本可以在建图后通过 `extract --split` 或独立的 `split --run` 命令调用 [semantic_split](../semantic_split/README.md)。拆分结果另存于 `fragments.jsonl` 和 `split_summary.json`，不改变本规范中的 `graph`、抽取状态与版本；片段是可共享节点的子图，动作间关系显式保留。
