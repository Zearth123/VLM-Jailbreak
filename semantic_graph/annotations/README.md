# 20 条人工参考图：待标注

本目录保存本次固定的 20 条目标、开发/留出划分以及三个盲标文件。**当前所有图为空，没有完成任何双人人工标注，也没有可用于报告忠实度的 gold。**

`sample_manifest.json` 记录官方来源 commit、原始数据 SHA256、随机种子与样本 ID。开发和留出各 10 条，各自覆盖六个语义类别。图规范使用 [SPEC.md](../SPEC.md)。

## 完成方式

1. 成员 A 与 B 分别填写 `annotator_a.jsonl` 和 `annotator_b.jsonl`。独立标注阶段只看原文与规范，不先参考机器抽取结果。
2. 在各自的 `annotation.annotators` 中填写本人标识；完成一条后将 `annotation.status` 改为 `annotated`，将图填入 `graph`。
3. 两人讨论节点跨度、类型、根和关系的分歧，在 `adjudicated.jsonl` 中保存一致结果。将状态改为 `adjudicated`，记录两位实际参与者，并在 notes 中保留争议与处理说明。
4. 使用 `evaluate --gold semantic_graph/annotations/adjudicated.jsonl` 评估。开发集和留出集分别报告；机器失败与缺失不能从召回分母删除。

## 每条复核的重点

- 请求框架和内部活动是否都保留，多个明确目标是否遗漏。
- 每个节点和关系是否有精确原文证据；原文没有的材料、步骤、参数一律不能加入。
- 否定词是否包含在约束中，约束是否连接到正确对象。
- 数量、单位、时间、来源、工具和目的是否被正确区分。
- 并列关系是否被误解为先后；来源是否被误解为第二个被操作对象。
- 即使所有字符位置都合法，关系含义仍可能有误，必须单独检查。

节点与边的证据使用 `{"quote":"原文片段","occurrence":1}`，无需手工计数字符偏移。详细方向与类型见规范。自由结构图的双标一致性应使用节点/关系匹配度；Kappa 仅适用于事先定义的离散标签，不能直接套在自由图上。

两个人的实际独立标注无法由程序代做；不要只填写两个名字就将机器候选图标成已复核。评估器只检查文件中的必要声明和结构，无法验证声明是否真实。
