# 08 · 设计依据:原方案的问题与取舍

本文件记录 `intro.md` 原始设计中的每个问题,以及为什么当前设计是现在这个样子。**目的是防止后来的实现者重新引入已被排除的组件。**

---

## 1. 因黑盒约束删除的组件

| 原组件 | 状态 | 原因 |
|---|---|---|
| GCG 对抗后缀 | **删除** | 白盒、需梯度;生成的后缀模型特异,迁移性差;乱码形式会被困惑度过滤器一眼拦掉 —— "看似乱码"恰恰是它的特征签名 |
| PGD 像素扰动 | **删除** | 过不了预处理:缩放、JPEG 压缩、任何输入变换都能摧毁它,而真实部署一定会缩放;加上白盒约束与频谱可检测性 |

**这两个组件恰好是原方案中最"高级"、也最容易被低成本防御干掉的部分。** 黑盒约束帮项目省掉了全部相关工程投入。

---

## 2. 逐条问题与取舍

### 2.1 分解阶段需要 LLM,而 LLM 有安全对齐

**原方案**:"用 LangChain 调开源大模型做信息抽取"。

**问题**:拿有害指令去调一个对齐过的模型做三元组抽取,它会拒绝。整个构建管线被它要攻击的同一类安全训练卡住 —— 死循环。

**取舍**:

- 对祈使句,语义图基本是平凡的。`spaCy` 依存句法就能拿到 S-V-O,**不需要 LLM、不需要 LangChain**。原方案在这里是过度工程。
- 真需要模型时,用**未对齐的小模型**(7B 足够),不用前沿模型。
- **允许的例外(2026-10 增补)**:冻结的**非对齐编码器**(CLIP 文本塔 / base LM / sentence-transformer)
  可以用于**计算切分代价**(哪条语义边可以断、断了损失多大,见 [12](12-vector-graph-splitting.md))。
  边界是:它只提供**向量**,不提供任何"内容判断";不得用对齐/对话模型(拒答是不可复现的隐藏变量),
  实现里对 id 命中 `instruct/chat/-it/guard/rlhf` 的模型默认直接拒绝。

### 2.2 语义降级(委婉化)在嵌入空间里几乎不改变任何东西

**原方案**:把"枪支"换成"发射金属抛射物的管状机械装置"。

**问题**:换的是**表面形式**,嵌入向量没变多少。而当前内容审核是嵌入分类器,不是关键词匹配。收益极低。

**更糟的反作用**:模型可能识别不出委婉语指代什么,于是"配合了但输出没用"。

**这里存在原方案完全没承认的真实张力**:**要足够无害以通过审核,又要足够具体以引出有用输出。** 这是核心约束,应当作为可扫描的参数,而不是当成一个"降级"步骤一笔带过。

**取舍**:改为**语境重构**(见 [04](04-modules.md) M3)。

### 2.3 核心假设从未被验证,且构造上就是脆的

**原方案**:"局部无害 ≈ 全局安全"是模型的认知偏差。

**问题**:这是断言,不是结论。而且它成立的条件是**防御方不做跨片段聚合** —— 而聚合是任何人看到"把恶意指令拆成片段"这个描述后第一个想到的防御。

**推论**:攻击的有效性完全依赖"防御方看不见整体",而"看不见整体"是最容易修的一种缺陷。把 N 个片段文本(加图像 caption)拼起来过一次分类器,整条链路归零。

**取舍**:把这个假设变成可测量量(逐片段 `sensitivity`),并在 P1 中直接检验(见 [07](07-p1-spec.md))。

### 2.4 跨模态不产生信息,只制造检测盲区

**原方案**:模态分散承载。

**问题**:拆分跨模态不减少需要传递的信息量,只改变分类器看哪里。纯粹是"防御盲区利用"。

**原方案还把两件很不一样的事情混为一谈**:

| 类型 | 内容 | 效力 |
|---|---|---|
| 语义级图像 | 画一个分子结构 | 带宽极低,SDXL 画不出可用步骤,模型也读不出来 |
| 排版级图像 | 把文字渲染成像素(FigStep 路线) | 真正有效,绕开纯文本审核;但过 OCR 的视觉审核能拦 |

两条路的效力和对应防御完全不同。

**取舍**:拆成 M5b-a / M5b-b 两条独立管线(见 [04](04-modules.md) M5b)。

### 2.5 目标设定反了:"让模型重组"是错的

**原方案**:"组合后能在模型内部的高层表征中重构出完整的攻击意图"。

**问题**:**模型一旦显式重组出完整意图,它就会对重组结果做安全判断,然后拒绝。重组恰恰是防御触发的那一刻,不是攻击成功的那一刻。**

**取舍**:改为"让组装后的输入读起来是一个普通的良性任务,而该任务的*自然完成*恰好输出有害内容"(见 [02](02-mechanism.md) §3)。

### 2.6 "内部重构"是假设,不是机制

**原方案**把从"拆分"到"内部重构"这一步当作给定。

**问题**:没有任何机制让模型把图文关联起来。若图文毫不相干,模型会当两件事分别处理。

**取舍**:M6 新增**黏合指令**要求(见 [04](04-modules.md) M6)。

### 2.7 图切分用错了工具

**原方案**:Louvain / min-cut。

**问题**:一条指令的三元组图通常只有 3–6 个节点,社区发现算法在这个规模上没有意义。

**取舍**:按语义子目标聚类;`$N$` 作超参扫描;增加**依赖保持约束**(原方案完全漏掉 —— 切断依赖边会破坏因果链,切出来的东西模型无法执行)。

### 2.8 没有威胁模型与成功判据

**原方案**:完全没有定义"什么叫攻击成功",也没有威胁模型。

**问题**:没有定义就没法测量,没法测量就没法改进。

**取舍**:建立三级判据(见 [01](01-threat-model.md) §2)+ 四实验条件(见 [05](05-experimental-setup.md) §2),评测复用 HarmBench。

## 3. 一处对原方案的正面确认

原方案中**最站得住的部分是模态分配**的想法本身 —— 只是它没有给出可操作的判据。

当前设计把它落成由 `serializable` 驱动的规则(见 [04](04-modules.md) M4),这是全部设计里最锐利的一条。

## 4. 相关工作定位(影响贡献声明)

| 工作 | 关系 |
|---|---|
| **Jailbreak in Pieces**(Vijay et al. 2023) | **最接近的先行工作**,多模态组合式拆分。与本方案高度重叠,**最需要正面处理** |
| **FigStep** | 排版型图像攻击,对应 M5b-a |
| **Crescendo / Skeleton Key / Deceptive Delight** | 黑盒重构型越狱 |
| **Qi et al. 2023** | 视觉对抗样本越狱(白盒,本方案不含) |
| **HarmBench** | 数据集与判官的来源 |

**本方案的真实增量**约为:**语义图形式化 + 可调切分策略 + 系统化的模态分配规则**三者的组合。

> **"提出新的攻击类别"这种写法会被上述工作打掉。** 写成"对已有组合式攻击路径的系统化与形式化刻画"更站得住。
