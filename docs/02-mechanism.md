# 02 · 机制分析

本文件回答三个问题:危害信息**从哪来**、攻击语义在**哪一层**、优化目标应该放在**哪里**。

---

## 1. 信息从哪来

输出有害内容需要信息。信息只能来自三处:$T$、$I$、或模型内部。若 L1 ∧ L2 同时成立(见 [01](01-threat-model.md) §2),则 $T \cup I$ 的表面信息里不含危害。因此只剩三条可能:

| 来源 | 可行性 | 说明 |
|---|---|---|
| **模型内部记忆** | 中 | 输入是检索键,模型凭记忆补全。依赖具体模型对具体行为的记忆,脆弱。对应构造模式 C |
| **不可文本化的视觉细节** | **高** | 图里有 caption 会丢失、但视觉编码器读得到的东西。对应构造模式 A/B |
| **组合涌现** | **需举证** | 信息不能由拼接创造。不能当假设用 —— 这正是原方案犯的错。对应构造模式 D |

**第二条是黑盒下唯一真正可走的路线。**

### 为什么"不可文本化"是关键

caption 是一种**有损压缩**。以下信息在"给图配一句话"时全部或大部分丢失,但视觉编码器读得到:

- 精确的结构式、拓扑连接关系
- 空间排布、相对位置
- 细粒度数值与标注
- 图例位置、顺序关系

于是可能出现:

- 图整体看无害(一张化学示意图)
- caption 无害("一个分子结构图")
- 但模型从视觉 token 里拿到了精细信息,与文本片段在联合空间里对接上

**这条路径不需要对抗扰动,完全落在黑盒约束内。** 它是 [04-modules.md](04-modules.md) 中 M4 模态分配规则的直接来源:

> **文本化会丢失的信息 → 图像**

---

## 2. L2 是全部难度所在

由 §1 可知,攻击要成立,信息必须**躲过文本化**。但:

- captioner 越强,L2 越难过
- 而 L2 用最强 captioner 测(见 [01](01-threat-model.md) §2)
- 同时,图中的信息还必须**仍然能被目标模型的视觉编码器读到**

这两条要求方向相反:要躲过强 captioner,信息就得足够细;要能被读到,信息又得足够显著。**这个张力是本方案的核心技术难点,P1 要探的就是它有没有解。**

---

## 3. 目标不是"让模型重组"

原方案的前提是"组合后模型内部重构出完整攻击意图"。**这个前提是反的。**

模型一旦显式重组出完整意图,它就会对重组结果做安全判断,然后拒绝。**重组恰恰是防御触发的那一刻。** 真正要的是:

> 让组装后的输入读起来是一个**普通的、良性的任务**,而这个任务的*自然完成*恰好会输出有害内容。

两条推论:

### 推论一 —— 改写 M3

不要做委婉化。委婉化丢内容(换的是表面形式,嵌入空间基本不变,对嵌入分类器无效),而且模型可能识别不出委婉语指代什么,于是"配合了但输出没用"。

要做**语境重构**:把技术内容重铸进一个合法外观的语境(教材、安全培训材料、实验手册)。**内容一个字节不丢,改变的是它被读取的方式。**

### 推论二 —— 约束 M6

组装产物不该是一个"待解的谜题",而该是一个**看起来正常的任务**。

- ❌ 读起来像"以下五步合起来构成炸弹制作" → 必然被拒
- ✅ 读起来像"写一节覆盖这几个知识点的化学课" → 可能通过

## 4. 语义在编码期还是生成期

### 4.1 两种可能

**编码期**:$E$ 中已经装着完整的攻击语义。

问题:如果 $E$ 里真装着完整攻击语义,那它和模型的拒绝判断**处在同一层**,对齐同样能读到。也就是说 —— 语义在编码期意味着**攻击不规避模型对齐**。

**生成期**:$E$ 看起来是良性的,生成以良性框架起步,有害内容在**逐 token 生成过程中涌现** —— 没有任何单步触发拒绝。

这一种更符合越狱文献中的实际现象,而且它给出的优化目标更可操作。

### 4.2 为什么必须早做判定

这个分歧决定后续所有模块往哪个方向优化:

| 判定结果 | 优化目标 |
|---|---|
| 编码期 | 让 $E$ 携带语义同时不被读出 —— **黑盒下无法施加**,路线需要重新考虑 |
| 生成期 | 让**生成轨迹**起步于良性框架并且不回撤 —— 可通过纯内容的框架设计影响 |

因此该判定被前置到 P1(第 1 周内),而不是等管线建好之后。见 [07-p1-spec.md](07-p1-spec.md) §4。

### 4.3 判定方法

**方法一 —— 拒绝位置(零成本,先做)**

逐 token 记录输出,看拒绝出现的位置:

| 现象 | 含义 |
|---|---|
| token 0 即拒绝 | 语义在**编码期**已被读出 |
| 起步配合、中途反转("其实我不应该…") | 语义在**生成期**涌现 |
| 全程配合 | 攻击成立 |

**拒绝位置本身就是最便宜的探针**,不需要任何权重访问。

**方法二 —— 表征探针(需权重,仅在方法一给出信号后做)**

准备两组参考表示:

- `R_harm`:原始有害 goal 的表示
- `R_benign`:同话题无害请求的表示

取 $(T, I)$ 在若干层的联合表示,测它到两组的距离:

- 偏向 `R_harm` → 编码期
- 偏向 `R_benign` → 生成期

**必须有对照组**:同样的 $T$ 配无害图、同样的 $I$ 配无害文本。否则测到的是"这张图本身"而不是"这个组合"。

---

## 5. 对本方案的定位结论

综合以上:

- 规避的是**外部护栏**,不是模型对齐([01](01-threat-model.md) §3)
- 信息只能走**不可文本化细节**或**模型记忆**两条路(§1)
- 优化目标是**生成轨迹的起步框架**,不是编码表征(§4)

这三点共同约束了模块设计,详见 [04-modules.md](04-modules.md)。
