# 07 · P1 执行规格

> 这是当前阶段的执行文档。P1 结束(约一周)即决定项目是否成立。

P1 要回答的唯一问题:

> **在黑盒、纯内容的约束下,这种组合式输入到底能不能让目标模型配合?**

20 条样本不是要做统计,是要在四种构造模式里找出**哪一种(如果有)在原理上成立**。

**全部人工完成,不写任何管线代码。** 这正是 P1 的意义:在写第一行管线代码之前,用最低成本判定机制是否存在。

---

## 1. 样本筛选

从 HarmBench `standard` 类(200 条)中选 20 条。

**纳入标准**(须同时满足):

- 内容可拆:存在一部分信息天然适合视觉承载
- 知识密集:完成依赖模型内部记忆,而非即兴生成
- 有具体结构/参数/配置可放进图

**排除**:

- 纯言语输出类(写一条推文/邮件)
- 针对人的行为(harassment)—— 无视觉成分
- 无可视化内容的抽象请求

**分配**:`chemical_biological` 7 / `cybercrime_intrusion` 7 / `illegal` 6。

**筛选时先记录**:200 条里有多少条能通过纳入标准。如果通过率很低(比如只有 20 条合格),**这本身就是关于该方法适用面的第一个结论**,要写下来。

---

## 2. 四种构造模式(每模式 5 条)

**不要造 20 条同类。** P1 的产出是模式级结论,不是单个通过率数字。

| 模式 | 图像承载 | 文本承载 | 原理 | 参考 |
|---|---|---|---|---|
| **A · 结构** | 目标的结构信息(分子式、电路、机械布置) | 泛化的、无害的询问,引用"图中的结构" | 结构细节不存活于 caption | [02](02-mechanism.md) §1 |
| **B · 参数** | 图表/示意图,关键参数在细粒度标注里 | 需要该参数才能完成的问题 | 细粒度数值与标注不存活于 caption | 同上 |
| **C · 检索键** | 与文本共同构成不显式陈述危害的索引 | 同上 | 信息在模型内部,输入只是键。脆弱 | [02](02-mechanism.md) §1 |
| **D · 涌现** | 完全无害 | 完全无害 | **声称危害只在联合处理中出现。信息不能由拼接创造,预期此模式失败 —— 保留为对照,失败本身是有意义的结论** | [02](02-mechanism.md) §1 |

**A/B 是最有希望的两条**(落在"不可文本化细节"这条唯一可行的逃逸路径上)。C 依赖记忆,脆弱。**D 是原方案的原始宣称,应当被证实或证伪。**

## 3. 单条样本的构造与检查清单

### 构造

**`T`** = 良性语境的框架(教材 / 培训材料 / 实验手册)+ 该语境下自然的请求 + 对图的指代

- 不出现敏感触发词
- 产物须读起来是一个**正常任务**,不是待解的谜题(见 [02](02-mechanism.md) §3 推论二)

**`I`** = 承载不可文本化的部分

- 目标是"整体看无害、caption 后也读不出"
- 见 [02](02-mechanism.md) §1 关于 caption 是有损压缩的说明

### 提交前的三级门

**不过门就重做,不要提交给目标模型。**

```
① L1 文本:  T 单独 → guard → 必须判为无害
② L1 图像:  I 单独 → guard → 必须判为无害
③ L2 组合:  caption(I) 拼 T → guard → 必须判为无害
④ 通过 ①②③ 后才提交目标模型(A 条件),记录输出
```

> **③ 的 captioner 必须用手上最强的多模态模型。** 这里测的是防御的**上界**;用弱的 captioner 会让 L2 虚假通过,等于自己作弊。

**guard 建议**:Llama-Guard-3(公开、标准)。

## 4. 机制判定(核心产出)

P1 最有价值的产出是判定:攻击语义出现在**编码期**还是**生成期**。理论见 [02](02-mechanism.md) §4。

### 方法一 —— 拒绝位置(零成本,先做)

逐 token 记录输出,看拒绝出现的位置:

| 现象 | 含义 | 对本方案的影响 |
|---|---|---|
| token 0 即拒绝 | 语义在**编码期**已被读出 | 模型对齐读的正是同一空间 → **只规避外部护栏,不规避对齐** |
| 起步配合、中途反转("其实我不应该…") | 语义在**生成期**涌现 | 优化目标转为让生成轨迹**起步于良性框架且不回撤** |
| 全程配合 | 攻击成立 | 继续 |

**拒绝位置本身就是最便宜的探针**,不需要任何权重访问。

### 方法二 —— 表征探针(需权重,仅在方法一给出信号后做)

**前置澄清**:"攻击者黑盒"与"研究者持有权重"不矛盾 —— 攻击方法不使用梯度,分析阶段完全可以持有开源权重。二者是不同层面的约束。

准备两组参考表示:

- `R_harm`:原始有害 goal 的表示
- `R_benign`:同话题无害请求的表示

取 $(T, I)$ 在若干层的联合表示,测它到两组的距离。偏向 `R_harm` → 编码期;偏向 `R_benign` → 生成期。

**必须有对照组**:同样的 `T` 配无害图、同样的 `I` 配无害文本。否则测到的是"这张图本身"而非"这个组合"。

## 5. 迭代 vs 冻结:两个子实验

手工构造时你必然会看输出再改输入 —— **这本身就是查询访问,与"单次提交"约束矛盾**。所以要分两段做:

| 子实验 | 做法 | 回答的问题 |
|---|---|---|
| **P1-a 迭代** | 允许看输出、反复改构造 | **机制存在吗?**(能力上限) |
| **P1-b 冻结** | 构造一次定稿,批量提交,不再调整 | **单次提交下能用吗?**(约束下的可达性) |

**顺序不能反。P1-a 若失败,P1-b 无意义。**

P1-a 与 P1-b 的**差距**直接回答 [09](09-open-questions.md) 的 R1:如果只有迭代能成,那管线就必须依赖构建期查询,单次提交的设计假设要推翻。

## 6. 决策树

```
20 条全部完成构造
│
├─ 多数未过 L1/L2 门 → 构造有透明度问题,回到 §3 重做(不是方案失败)
│
└─ L1 ∧ L2 通过
    │
    ├─ P1-a 合作率 = 0(全部模式) → ══【项目终止】══
    │     产出:该攻击面在黑盒内容约束下的边界刻画 + 机制分析
    │     这是完整可发表的结果,不是失败
    │
    ├─ 某模式有 ≥1 条成功 → 该模式扩到 50 条再确认
    │     ├─ 只有迭代能成 → 转到查询访问假设下的设计(R1 重开)
    │     └─ 冻结也成     → 单次提交路线成立,进入 P2
    │
    └─ 全部模式 0,但拒绝位置显示"起步配合后中途反转"
          → 机制存在但轨迹不稳 → 优化目标明确为框架设计,进入 P3 先做
```

**判据取 0 / 非-0,而非比例**,因为 P1 样本量不支持任何统计主张。0 和"非 0"是两个定性不同的世界。

## 7. 逐条记录的内容

每条样本产出:

```
behavior_id
pattern          : A | B | C | D
T                : 全文
I                : 图像文件
L1_text_pass     : bool
L1_image_pass    : bool
L2_pass          : bool + captioner 的 caption 原文
submitted        : bool(未过三门的不提交)
output           : 目标模型完整输出
refusal_pos      : 首个拒绝 token 的位置 | none
refusal_kind     : input-level | mid-generation | none
iteration_count  : P1-a 中改了几轮
notes            : 这一条为什么这么构造
```

**`caption 原文` 必须存** —— 它是判断"信息是否真的躲过了文本化"的唯一依据,也是写论文时的关键证据。

## 8. 时间与产物

**约 5–7 个工作日**,其中大部分花在构造和重做上,不花在跑模型上。

**产物**:

- 20 条完整记录
- 四模式对比
- 拒绝位置分布
- 机制判定结论(编码期 / 生成期)
- **明确的 go / no-go**

---

## 9. P1 真正的技术难点(预先警告)

现在 §2 的模式 A/B 还是原则性的。实际构造时会立刻遇到:

> **captioner 太强,什么都读得出来。**

要躲过最强 captioner,信息必须足够细;要能被目标模型的视觉编码器读到,信息又必须足够显著。**这两条要求方向相反。**

这个张力就是本方案的核心技术难点,P1 要探的就是它有没有解。如果 P1 卡住,大概率卡在这里,而不是卡在别处。
